### Code paths reviewed

Authorization and role checks cover progress, educator analytics and game sessions. User IDs come from validated auth claims; educator role is read from the server-side user record; there is no public educator-role mutation route. Guest challenge IDs intentionally act as random capabilities and cannot save to a signed-in account. SQL is built with Drizzle schema objects and bound values; no command execution, runtime template evaluation, untrusted server-side fetch target, file upload/write endpoint, webhook receiver or arbitrary deserialization path was found. Scenario loading reads local known directories and validates JSON. Rich text renders React nodes rather than raw HTML. Chart style injection is fed by developer configuration, not a user-editable setting. API responses are now no-store and unknown API routes return JSON 404 rather than the SPA.

This manual review is not CodeQL coverage. DB RLS is not a substitute for the application's server-side authorization: browser clients have no DB credentials, but live grants, public access, extensions, administrative exposure and row-level policies were not accessible to verify. No AI-feature tool execution path exists in this repository; coding-agent/gateway permissions and logged responses are a separate unverified environment.
